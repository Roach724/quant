# W3-W4 实施计划 — 5m 频率 + 评估决策

> **For agentic workers:** Use subagent-driven-development. Steps use checkbox syntax.

**Goal:**

## W3: 5 分钟频率 + Cron

### W3-1: 5m PaperRunner 适配

**Files:** Modify `run_paper.py` `_sdk_data()` method

BQ loader 当前硬编码 `{market}_bars_1d`，需改为根据 data_source 选择频率表。

**评估**: `_sdk_data` 目前只查 1d 表。W3 需要支持 5m 表。改动很小——加一个 `frequency` config 参数。

- [ ] **Step 1:** 给 PaperRunner config 加 `frequency` 字段（默认 `1d`）
- [ ] **Step 2:** `_sdk_data` 读 `{market}_bars_{frequency}` 
- [ ] **Step 3:** 更新 CLI `--data-source bq` 支持 `--frequency 5m`
- [ ] **Step 4:** 验证: `run_paper.py --data-source bq --frequency 5m`

### W3-2: 5m Momentum Paper Run

- [ ] **Step 1:** 用 5m 数据跑 SimpleMomentum paper
  ```bash
  bash scripts/run_paper_momentum.sh us 2026-05-01 2026-05-28 100000
  # 加 --frequency 5m
  ```
- [ ] **Step 2:** 对比日线 vs 5m 结果（Sharpe/MaxDD/WinRate 是否有显著差异）
- [ ] **Step 3:** 调整策略参数适应 5m（lookback 从 20 天 → ~78 个 5m bar = 1 天等价）

### W3-3: Cron 定时 Paper Runner

- [ ] **Step 1:** 创建 cron 脚本 `scripts/cron_paper_momentum.sh`（交易日盘中每 5m 触发）
- [ ] **Step 2:** 设置 OpenClaw cron job (Mon-Fri, 14:30-21:00 UTC, every 5m)
- [ ] **Step 3:** 日志采集 + 错误告警

### W3-4: 观察 & 调试

- [ ] **Step 1:** 跑 3+ 个交易日
- [ ] **Step 2:** 检查日内表现一致性
- [ ] **Step 3:** 修复任何运行时问题

**W3 成功标准**: 5m Paper 连续 3 个交易日无报错，日内表现与回测偏差 < 20%。
